Application documentation

From product intent to reusable test intelligence.

TestPilot AI converts pasted or uploaded requirements into structured manual and automated test cases. Its functional agents make each responsibility explicit, independently validate generated output, and retain approved suites for future use.

Open Test DesignerOpen API Docs

How the application works

A coordinator runs four focused agents in a governed sequence.

01 · INGEST

Input Agent

Normalizes text or securely extracts requirements from uploaded documents.

02 · DESIGN

Generator Agent

Produces risk-based manual and automation scenarios through GitHub Copilot.

03 · VERIFY

Validator Agent

Checks the suite independently and returns a quality score with findings.

04 · REUSE

Storage Agent

Stores validator-approved suites and retrieves exact matches in future runs.

Standardized test generation

Every requirement uses the same governed format and quality basis so test suites remain consistent, comparable, exportable, and easy to use across teams.

Generation basis

  • Critical business path and highest product risks
  • Important positive, negative, boundary, authorization, accessibility, and failure behavior where relevant
  • Four to five concise scenarios with at least two automation and two genuinely manual cases
  • Synthetic test data and explicit acceptance-criteria traceability

Standard case structure

  • Stable ID, title, and objective
  • Category, priority, and manual/automation classification
  • Case-specific feasibility reason and preconditions
  • Actions with observable expected results
  • Test data, tags, acceptance-criteria mappings, and optional SpecFlow Gherkin

Application use cases

Common ways quality teams can use the pipeline.

Story refinement

Paste a user story and acceptance criteria to expose testable behavior, gaps, assumptions, and negative paths before development begins.

Document-to-tests

Upload a requirements document, spreadsheet, PDF, or UI image and convert its extracted content into a structured suite.

Manual and automation planning

Separate repeatable deterministic scenarios from exploratory, visual, usability, and human-judgment checks.

BDD preparation

Generate SpecFlow-compatible Gherkin scenarios while retaining structured steps for CSV, JSON, and Jira workflows.

Quality review

Use the independent validation report to detect missing coverage, weak traceability, duplicates, vague wording, and unobservable results.

Regression reuse

Return a previously validated exact-match suite from local organizational memory without another premium generation request.

Supported inputs

Direct text

User stories, feature descriptions, business rules, and acceptance criteria up to 30,000 characters.

Business documents

Word `.docx`, text PDF, Excel `.xlsx`, Apple Pages `.pages`, and Apple Numbers `.numbers`. iWork packages are read from their local Quick Look preview or legacy XML; binary-only files must be exported from the Mac as PDF or XLSX.

Images

PNG and JPEG through local Tesseract OCR. Files are limited to 15 MB, and oversized images are rejected safely.

Outputs and future reference

Each suite includes categorized test cases, priority, manual/automation classification, feasibility rationale, preconditions, steps, expected results, test data, tags, and acceptance-criteria mappings.

Manual test cases

Numbered actions with observable expected results for review and execution.

BDD scenarios

Copy-ready SpecFlow Gherkin using Scenario or Scenario Outline where appropriate.

Validated memory

Only newly generated suites without validation errors are written to the local SQLite store. Cached results are revalidated when retrieved.
