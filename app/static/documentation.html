Architecture

Markdown-directed, Python-governed

The system deliberately separates readable agent behavior from executable controls.

MD

Markdown owns intent

Base agents define roles, reasoning policies, input/output expectations, and quality standards.

  • .github/agents/*.agent.md
  • Project-specific profile overlays
  • Version-controlled BRD knowledge
→
AI

Shared Copilot runtime

One runtime owns authentication, restricted sessions, timeouts, events, JSON extraction, and typed output validation.

  • app/agents/runner.py
  • Declarative output contracts
  • Tools and memory disabled by default
→
PY

Python owns control

FastAPI and deterministic services enforce schemas, quality gates, storage, exports, security, and external actions.

  • Pydantic contracts
  • SQLite exact-match memory
  • Explicit Jira authorization
Why separate profiles?

The same reusable agents can support multiple products without leaking automotive rules into unrelated projects. The selected profile is composed into the agent prompt at runtime.

Quality standard

Consistent, traceable generation

Every output follows typed structures and the selected project policy.

All test cases

Canonical case structure

  • Stable ID, concise title, objective, category, and priority
  • Explicit manual or automation execution mode
  • Case-specific feasibility reason and preconditions
  • Actions paired with observable expected results
  • Synthetic test data, tags, and BR-QT traceability
Automation

Executable BDD contract

  • Scenario or Scenario Outline with complete Examples
  • Concise Given, When, Then and optional And/But
  • Maximum four executable lines per scenario
  • Typed data suitable for ReqnRoll bindings
  • Approved financial oracle required for exact calculations
Manual

Acceptance evidence

  • Human-executable counterpart for every BRD validation
  • Clear operator action and observable evidence
  • Consumer Duty and disclosure comprehension review
  • Accessibility and customer/business presentation checks
  • gherkin: null for structured manual cases
Quality Gate

BRD completeness

  • BR-QT-001 through BR-QT-028 remain traceable
  • All applicable validation categories are represented
  • All 19 business error codes use the BRD schema
  • Unsupported formulas and regulatory wording are rejected
  • Exact calculations require approved golden references

Developer reference

Integrations and API

All mutation endpoints remain local and controlled; Jira publication requires an explicit user action.

POST/api/agent/run

Ground, recall, generate, validate, and store a suite.

POST/api/generate/document

Extract a supported document and run the governed pipeline.

POST/api/step-definitions/reqnroll

Generate typed C# bindings from a Quality Gate-approved automation suite.

POST/api/test-data

Fill missing values with case-aligned synthetic data.

POST/api/execution

Validate and summarize supplied execution results.

POST/api/defects

Create review-required defect drafts from failures.

POST/api/metrics

Calculate coverage, execution, and defect metrics.

GET/api/agents

List functional agents, responsibilities, runtimes, and capabilities.

POST/api/context-converter/{format}

Convert an approved suite to feature, CSV, XLSX, or JSON.

POST/api/jira/publish

Attach explicitly selected tests to Jira Cloud.
