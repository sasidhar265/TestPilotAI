Application guide

Your guide to confident finance testing.

Auto Finance Quality helps you create manual test cases and automation scenarios, check requirement coverage, and export test files. Start with a vehicle finance requirement, quotation BRD or Jira story.

Open Quality workspace →Get started
Key terms

What the words mean

Test suite: a collection of test cases.

Agent: a component with one job, such as preparing input or checking tests.

BDD / Gherkin: scenarios written as Given (setup), When (action) and Then (expected result).

Quality Gate: automated checks on the test design.

Design quality and test results are different

A Quality Gate pass means the generated test design passed the application’s checks. A test passes execution only after it runs against an application and its expected result is confirmed.

01

Create your first test suite

Follow these steps in Quality workspace.

  1. Stage 1 · Read requirements. Paste a command prompt, upload a BRD with the + control, or connect a Jira ticket. Check shared business rules and select Read requirements.
  2. Stage 2 · Create stories. Review each story’s business need, source excerpt and acceptance criteria. Edit where needed, then select Use these stories.
  3. Stage 3 · Create scenarios. Review story-linked preconditions, actions and expected outcomes. Select Use these scenarios when the coverage is ready.
  4. Stage 4 · Create test cases. Choose Functional, Automation (BDD / Gherkin), Non-Functional, or Both. Choose API or UI testing for functional and automation coverage, or Performance or Database testing for non-functional coverage. Generate cases, review Quality Gate findings, and use the existing approval, View and Download options.
  5. Stage 5 · Execute. Record manual outcomes and actual results. For automation, install the reviewed pack in the configured ReqnRoll project and configure its target environment. Refresh the execution plan, review the feature list and run. Individual results appear when the runner finishes.

Changing source requirements clears downstream drafts. Drafts stay available while navigating workspace pages, but reloading starts a new workflow. Stories are not published to Jira automatically.

03

Agents and responsibilities

Each agent has a specific job. Some use AI; others use application rules, stored data or a test runner. They run when their task is needed, so the list does not mean every agent runs for every request.

The usual generation flow

Prepare the input → apply business rules → look for a saved match → plan and write tests → check the design → store validated results. Export and execution are separate actions.

04

What you can provide

Clear requirements give the agents a better basis for useful tests.

Requirement text

Enter 10–30,000 characters. Describe the feature, valid and invalid behaviour, and expected outcomes. Supply approved request examples and expected values when exact API or calculation checks are needed.

Documents and images

Upload DOCX, text-based PDF, XLSX, Pages, Numbers, PNG or JPEG, up to 15 MB. Image text extraction requires Tesseract on the application host. Scanned PDFs need text recognition first; export unreadable Pages or Numbers files to PDF or XLSX.

Jira stories

Use + → Link Jira ticket, enter an issue key or browse URL, then choose Connect. The application imports the summary, description and available acceptance criteria for you to review.

Business rules

Shared rules apply to generation across this workspace. Project profiles add domain-specific guidance. Rule IDs and business constraints depend on your project; quotation-specific rules are not universal requirements.

05

How to review generated tests

Check the business meaning as well as the automated validation result.

Manual tests

Review the objective, preconditions, actions and expected result for each step. Confirm that a person could perform the test and judge its outcome. Check any supplied test data.

Automation scenarios

Check the Given / When / Then scenario and any example rows. Confirm that the scenario describes observable behaviour and uses the correct inputs. Generated code still needs review and target configuration before execution.

Coverage and validation

Traceability links show which requirements a test is intended to cover. The Quality Gate checks structure and applicable design rules. Inspect errors, warnings and missing coverage before accepting the suite.

Review and acceptance

Review lets you submit comments and regenerate an individual case. Approve selected records acceptance under the reviewer name you enter. Downloads become available according to suite validation and output type; human acceptance is a separate record.

06

View, download and share

Available actions depend on the generated suite.

Manual suite downloads

Validated manual-only suites can be downloaded as Excel, CSV, PDF or JSON. Spreadsheet and document downloads are disabled when the suite contains automation cases.

Automation files

View or download the Gherkin feature, step definitions or full automation pack. Choose C#, Java, Python, JavaScript, TypeScript or Ruby. C# packs use ReqnRoll, which connects Gherkin steps to C# code.

Full automation packs

Packs include scenarios, bindings, supporting implementations, input data and framework configuration. Review the files, supply the target settings and run the pack in its configured environment.

Jira and accepted outputs

Use the Jira action to attach selected tests to the chosen issue. Approve selected stores acceptance artifacts and shows a receipt. These actions require the relevant fields and, for Jira, a configured connection.

07

Understand execution results

The Run BDD tests button runs the repository’s configured C# suite. It does not execute the automation pack you just generated.

Read the dashboard

Recorded runs, latest pass rate, failures and duration come from repository BDD history. The selected-run chart shows passed, failed and not-run counts when results are available. A missing result is shown as unavailable.

Run generated tests

Download and review the generated pack, configure its target URL and required credentials, and run it using its framework. For a C# pack, run dotnet test Automation.csproj from the extracted pack directory. Inspect the discovered scenarios and execution results.

Use the right evidence

A repository BDD pass describes that repository run. It does not demonstrate that a generated suite passed against your target application.

08

How the application works

This is useful background when setting up the application or investigating a problem.

AI generation

The LLM selector shows models available through connected accounts. Automatic fallback, when selected, tries Copilot, OpenAI, Gemini and Codex in that order. Model availability depends on the deployment and account permissions.

Rules and stored knowledge

Agent instructions and project profiles guide generation. Application code checks outputs and manages exports. Validated exact-match suites can be stored and rechecked for reuse; accepted output artifacts have a separate approval record.

Data handling

Document text extraction happens on the application host. Requirements and relevant context are passed to the selected AI provider for generation. Shared rules and saved records belong to the deployed workspace.

When something fails

Read the message, copy its reference ID and search Runtime logs. If no models are available, use Refresh models and check the connected account. If document extraction fails, try a supported text-based export. Log entries are held in memory and clear when the application restarts.

10

Integrations and API

For developers and administrators. The API reference lists the complete request fields and responses.

Generation and agent registry

POST /api/agent/run generates from text; POST /api/generate/document accepts a document. GET /api/agents lists registered roles. Registration does not verify model credentials or execution readiness.

Code and acceptance

POST /api/step-definitions/bindings generates bindings in a selected language. POST /api/step-definitions/reqnroll provides C# generation. POST /api/output/accept records selected-case acceptance.

Execution and logs

POST /api/automation/run runs repository BDD tests. GET /api/automation/history returns their history. GET /api/logs returns recent entries or entries for a reference ID.

Additional API workflows

The APIs also support test-data helpers, supplied-result summaries, defect drafts and metrics. Formal requirement versions, baselines, cycles and audit records are available under /api/stlc; these management forms are not part of the Quality Lifecycle page.

Need setup details or request fields?

Open the API reference. Jira actions require configured Jira credentials and issue permissions; automation requires its runner and target configuration.
